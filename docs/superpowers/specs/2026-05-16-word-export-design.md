# Word (.docx) Export for PMS Reports

**Date:** 2026-05-16
**Status:** Approved
**Stakeholder:** Robert Friedrich (PRRC/QM domain expert)

## Problem

PRRCs and QM teams work in Word, not Excel. The current report system generates PDF (read-only) and Excel (data-oriented). Regulatory professionals need an editable document format they can annotate, correct, and include in QMS binders. Robert estimates 99% of customers would prefer a Word report they can edit alongside the PDF.

## Decisions

- **Library:** `docx` npm package (Approach A — programmatic document builder)
- **Format coexistence:** Word is added alongside Excel — both remain available
- **Document structure:** Mirrors the PDF report layout (cover + summary + FSN tables by category)
- **Plan gating:** Starter, Pro, Enterprise only. Free/trial users cannot generate Word exports.
- **No quota:** Word generation is not quota-gated (unlike PDF). It's gated by plan tier only.

## Document Structure

### Page 1 — Cover / Summary

- Neuridion header text
- Title: "Post-Market Surveillance — Field Safety Notice Review"
- Metadata table: device name, manufacturer, EMDN code, device class, review period, generation date
- Summary stats table: total FSNs, potentially relevant, requires review, not relevant, AI filter unavailable (if any)

### Pages 2+ — FSN Tables by Category

Each section has a colored header bar and a table of FSNs:

1. **Potentially Relevant** (green accent) — Title, Manufacturer, Date, Source URL, Assessment rationale, Confidence %
2. **Requires Further Review** (yellow accent) — same columns
3. **Not Relevant** (grey accent) — compact layout: Title, Manufacturer, Date, Source. Truncated rationale.
4. **AI Filter Unavailable** (red accent, only if filter_failed rows exist) — same as compact layout

### Footer

"Generated by Neuridion — Post-Market Surveillance Platform" + page numbers on every page.

### Styling

- Font: Calibri (Word default, universally available)
- Brand colors: #0F1F3D (dark navy headers), #0B7C72 (teal accents)
- Color-coded section headers matching assessment category
- Professional table formatting consistent with PDF output

## Architecture

### New Function: `buildDocx()`

Location: `app/api/reports/route.ts` (alongside existing `buildExcel()` and `buildReportHtml()`)

```
function buildDocx(
  rows: FsnRow[],
  meta: { device, manufacturer, period_from, period_to, emdn_code?, device_class? },
  termsUsed: TermsUsed | null,
): Promise<Buffer>
```

Same signature pattern as `buildExcel()`. Returns a Buffer containing the .docx file.

### Report Generation Flow (POST /api/reports)

1. Build Excel (always)
2. Build HTML (always)
3. Check user plan — if Starter+, build Word .docx
4. Check PDF quota — if allowed, build PDF
5. Upload all generated files to Supabase Storage
6. Store `report_docx_path` on `search_runs` row
7. Return signed URLs: `{ html_url, excel_url, docx_url, pdf_url, pdf_status }`

### Database

New migration: add `report_docx_path TEXT` column to `search_runs` table.

### Download Endpoint (GET /api/reports/[id]/download)

Add `format=docx` support:
- Returns signed URL for the .docx file
- Content-Type: `application/vnd.openxmlformats-officedocument.wordprocessingml.document`
- Filename: `FSN-Report-{device}-{period}.docx`

### Plan Gating

Check user's plan in the report generation route. Only generate .docx if plan is `starter`, `pro`, or `enterprise`. Return `docx_url: null` and `docx_status: 'plan_restricted'` for free/trial users.

### Frontend

- Archive/results page: add "Word" download button alongside PDF and Excel
- Free/trial users: button is disabled with "Starter+" badge tooltip
- Download triggers GET `/api/reports/[id]/download?format=docx`

### Landing Page

Update report-related copy from "PDF + Excel reports" to "PDF + Word reports" per Robert's feedback.

## Dependencies

- `docx` npm package (install via `npm install docx`)
- New Supabase migration for `report_docx_path` column

## Out of Scope

- Word template customization by users
- Replacing Excel with Word (both coexist)
- Word-specific quota tracking (gated by plan only)
