## 3. Completed work

### A. MHRA source document monitoring
- Attachments listed with GOV.UK metadata; `raw_content` unchanged so existing text hashes stay stable.
- Document monitor: authority hosts only (redirects re-checked), ETag / Last-Modified revalidation, sha256 over bodies, 25 MB cap, per-run document cap.
- Append-only `source_document_versions` history. Optional byte archive to the private evidence bucket (`SOURCE_DOCUMENT_ARCHIVE=true`).
- Change semantics: attachment digest tracked apart from text. A PDF replaced at the same URL counts as a change. A degraded observation never overwrites a complete record or counts as a change.
- Detail-page failures are now reported (previously silent fallback). Canonical read/upsert failures mark the source partial.
- Covered date ranges re-verify their attachments, so old notices are checked too. Scheduled ingestion does the same.
- Input currency: each run's screened state is compared at read time with the current stored record. Superseded inputs show on the run page and in every report format. Approved runs are never mutated.

### B. Reviewer workflow
- Owner assigns and revokes reviewers per run (append-only revocation). Review inbox page and API.
- Active assigned reviewers open the run page in reviewer mode: results and adjudication only.
- Approval sets `approved_by` / `approved_at` and keeps reviewer attribution. Approval stays owner-only.
- Self-approval is computed from the recorded reviewer and the approver's own final dispositions.
- Run page shows the API's real 403/409/422 reasons; approval confirmation is an accessible alertdialog.

### C. Previous-cycle comparison
- New, removed, modified (text or attachment digest) and decision-changed records, with AI vs human origin.
- Scope changes (profile fields, search terms, sources, period) reported separately from new evidence.
- Absence from a degraded or unsearched source is "unverified absence", never "removed". Any degraded side sets `comparable=false` and every explanation states it.
- Owner-only read API; component on the run page; included in reports.

### D. QMS reporting and exports
- Report format v3: one provenance model rendered identically in PDF, Word, Excel and HTML (reviewer and approver names, same-person disclosure, models, prompt and ruleset versions as recorded, record digest, input currency, previous-cycle comparison).
- Source URL per record in every format, including Word. Document reference anchored to the run date.
- v2 reports are refused at download and must be regenerated.
- Runs approved before record-level adjudication was enforced get an explicit explanation and a run-page banner.

### Defects fixed outside the workstreams
- Evidence reads were capped at 1,000 rows. 32 production runs exceed that (largest 7,628). Reports, run page, run API and adjudication view now page through all rows and fail closed on error.
- `GET /api/search-runs/[id]` picked an arbitrary decision from append-only history; it now takes the latest.

## 8. Database and RLS

- New migration `20261010190000_document_monitoring_and_review_attribution.sql` (schema 76): attachment columns on `fsn_canonical` and `fsn_results`, `source_document_versions`, `search_runs.approved_by/approved_at`, `run_reviewer_assignment_revocations`.
- New tables: RLS on, no policies, anon/authenticated revoked, service_role SELECT/INSERT, append-only triggers. Repeatable.
- Production advisor: 20 RLS-on/no-policy tables (intended service-role only); leaked-password protection disabled (WARN).
- Production data notes: 18 runs are `approved` with 0 adjudication events (approved before the gate existed; 16 on degraded runs). 59 runs hold legacy (pre-v2) reports, 0 hold v2. All need regeneration; the 18 approved runs cannot be regenerated under current gates and need a new search.

## 9. Security

- Fixed: silent truncation of evidence reads; silent MHRA detail fallback; SSRF surface in document fetching constrained to authority hosts with redirect checks and size/time limits.
- Assignment API: owner-only, 404 for others, ids-only audit events, rate limited. Email lookup reveals account existence to an authenticated run owner only.
- Open: enable leaked-password protection in Supabase Auth. Tenant isolation relies on application filters over the service-role client; there are no RLS policies to back it up. Secret scanning is not configured in CI (recommend GitHub secret scanning / push protection; history previously contained credentials in `.claude/settings.json`, rotated per PROGRESS.md).
- Build depends on fonts.googleapis.com at build time; a Google Fonts outage fails a deploy.

## 10. Benchmark

`benchmark/accuracy-gate` requires a frozen, PRRC-adjudicated dataset with a recorded hash. None exists in the repo, and production has no adjudications to build one from. No accuracy figure is claimed. Synthetic tests prove code paths, not real-world screening accuracy.

- No organisation model; reviewer assignment is sharing by the owner.
